# Sol 独立撰写操作指南

适用于本库的能力组、技艺、法术及批量规则转换。目标是只凭本库和本次需求，交付效果完整、依据可追溯的资源。以下总结军伍、狂岚、正十七及帝国魔法整理中的经验；它们是执行方法，不把个案裁定升级为全局规则。

## 最短执行流程

1. **固定任务。**分清新写、局部修订、原文转换。记下对象、等级、禁用项、必须保留的效果、已授权的修改范围；已有信息直接复用，不让用户重复填表。修订先找到指定版本，不能凭印象重建初版。
2. **固定规则口径。**顺序为本次明确要求 → 901 快照 → 未被替代的 PHB → 本项适配的 RE。只取相关[规则卡](common_rules.md)与[特性卡](traits.md)，记录需要单项适配的差异。
3. **确认用途和完整来源。**新写先说明资源实际解决什么问题；转换先读完整条目和它引用的基础机制。表中无直接价格的机制，依[类比核算](calibration.md#按机制寻找样板)找 1—3 个强相关完整近例。已有证据同批复用。
4. **写完整效果，再核三本账。**分别列模板容量、实际投入估价、XP 取得价格。核进阶的新增／替换／继承，以及本体与配套的实际配合。原文整包转换先核改变了哪些条件，无须为每个未改的效果重新发明组件单价。
5. **直接修正确定错误。**算错、抄漏、动作栏与正文矛盾、失效链接、遗漏原文效果，在已授权范围内修正。若用户只要求列问题或效果保持不变，就遵守该范围；不能借自查重做设计。
6. **做一次针对性验收并交付。**复杂交互用一个短场景走完；批量任务另核逐源覆盖。交付玩家正文、简短核算记录和必要目录，说明实际检查结果。只对新发现的具体问题补查，不循环启动整套评审。

只有查过相关资料仍不能判断、且会实质改变身份、核心效果或价格的问题才询问用户。把问题缩到一个明确选择，继续处理无依赖部分；不把修正已知错误变成再次审批。独立执行仍须诚实保留无法核定的部分，不能用默认值伪装已核定。

## 设计和预算中踩过的坑

| 曾出现的问题 | 以后怎样处理 |
| --- | --- |
| 用攻击／防御＋3封顶，靠大量限制或空预算控制 T3。 | D/C 是资源等级，T 档是世界定位。按特性表和完整近例核强度，再用代表角色检查实际表现；不自造统一加值上限。 |
| D 阶能力组几乎全换属性；随后又把数值训练视为没有设计价值。 | 属性并非能力组禁区。本库每阶最多投入两个同级特性强化属性，且不要求用满；常规攻防、技能和耐受仍可表现训练。 |
| 通用军伍变成盾兵专属，或每次反馈都触发整套重写。 | 简核代表岗位是否受益；护卫等专职内容放可选分支。保留用户指定的骨架，只动本次允许修改的条目。 |
| 为填容量加出背人更快、连击顺手拔武器、治疗附赠技能等级等不自然效果。 | 从用途判断每个效果是否需要。删去牵强附加值；不适合单独购买的条目可合并或删除，受修订范围约束。 |
| 把“不要硬凑”理解为半个能力组长期留空，仍以完整进阶价交付。 | 允许余量，但须检查购买价值。围绕同一用途改善进阶或配套；若仍不足，明确说明组合／定价尚未成立，不把模板合法当作价值充分，也不按空额比例自动打折。 |
| 忘记技能树奖励，或看到总额相等就宣布核价完成。 | 能力组本体与树入口分账；已付入口下每项技艺按基础 3＋奖励 1 个同级特性核容量。容量、估价、XP 各自有依据，不能倒填组件价格。 |
| 只找字面完全相同的资源，或只读高阶大包后判定低阶不能做。 | 按机制和近义词跨类别检索，优先同阶、低阶近例。技能等值、属性成功关联、选敌、换位、治疗、反应等都适用；没有独立拆价不等于无法作有界类比。 |
| C 阶只写威力＋1，没检查配套法术是否真的使用威力或施法检定。 | 用一项实际配套法术算出进阶收益。定值效果不为兑现专精加值补造检定；新增授术、缩时或其他用途须有预算和作用对象。数值进阶本身并非错误。 |
| 修一个问题就新增一条僵硬设计禁令。 | 区分通用规则、本库约束、本批约定和单项裁定。每阶属性预算上限是明确的库内约束；每阶必须有招牌、禁止普通加值、所有人必须共用一套动作循环，都不是。 |

预算细节沿用[特性速查](traits.md)和[类比核算](calibration.md)，不在这里再建立一套价格表。价格说明须能回答“为什么是这个模板／阶段、哪些变化影响成本”；不能只写“共四个特性，所以 25 XP”。

## 规则核对要落到实际结算

- **动作看数值和时机。**RE 可能把 4AP 格挡称为标准动作，901 已确认映为移动动作。动作补偿读 T-24：适用的 4AP 代价补次级特性，不能按名称误领同级补偿；用户给正十七指定的 4C 容量是单项口径。共付一次动作不逐组件重复领补偿。
- **动作折算与预算分开。**全局已确认的 2／4／6／8AP 映射见 CR-04。其他 AP 价、减费、恢复、预支须写本项方案；本批魔法采用的奇数落档、10／12AP、跨轮 14AP 处理不能自动推广全库。折算后仍须明确动作归属、次数、完成时点和反应锁，不重新建立 AP 池。
- **防御、攻击 DP、上限、伤害减免分层。**明确采用 RE 的破甲不穿 DR，余量可破硬度；削去防御可能增加最终攻击骰池，不直接提高伤害上限。防御在攻击 DP 中只扣一次；定值豁免法术不另扣一次被动防御。
- **固有性质和新增保护分账。**某种减防本来不削偏斜，这部分不重复计价；抵抗整体减防、明确无视偏斜及伤害吸收是不同交互。保留“多重攻击＋环境减值”等用户指定措辞时，还要交代作用于哪个模式、是否叠加、持续多久；不能擅自改写成另一类别。
- **相似名称不保证相同机制。**属性总值、传奇属性点、固定自动成功、RE 附加成功、一次检定的成功数须逐项区分。法术抗力按本项采用的原文核，不凭名称补出耗能抵消；可打灵体不等于拥有完整幽冥关键字。
- **九属性、专业和资格不能机械替字。**合并属性后不重复相加；有效技能只取一个匹配子技能。“或”保留择一，“同时要求”保留双资格，双资格不等于两个子技能同时加骰。NPC 福利、学习资格和免费技能等级各自分清。
- **能量池必须写来源和完整运作。**查普通池、能力专用池、角色特例，不因数值看起来奇怪就另造公式。例如 RE 普通精神池的除以四与艾利特殊池不能混用。正文写清上限、恢复、沿用已有池及增储作用；“魔力增储”四字不能代替效果。
- **治疗、状态和物品算式按具体机制。**快速医疗与治疗点不一定采用同一 B/L/A 比率；轻度减值、重度后果、免疫及去除逐一核。物品硬度、生命和坠物不能随意拼接 PHB 与 RE 两套公式；正式公式和示例冲突时，比较上下文及其他例子，记录采用依据，改不动的原书照原样保留。
- **XP 分清用途。**学习价、升级差价、内部构造额度、逐件制作费与旧材料“分”不是一笔钱。旧自学价只在本项接入后使用；原生 C 法术不强加不存在的 D 先修。901 不因训练或阅读天数自动产出 XP。

相关原文入口：[能量池](../content/RE/01_rules/02_战斗与动作/能量池.md)、[施法规则](../content/RE/01_rules/02_战斗与动作/施法规则.md)、[自学规则](../content/RE/01_rules/03_其他规则/自学规则.md)、[物品关键字](../content/RE/01_rules/04_附录/物品关键字.md)。只读本次触及的段落。

## 批量转换怎样保证不漏

1. **先建清单再分章。**逐源记录文件相对路径、原文名称与行号、原目录等级、条目实际等级。标题识别只是辅助；检查尾段、嵌入变种、无独立标题条目和引用其他条目的效果。原目录与正文价格／等级冲突须登记核对，不按目录强改。
2. **每个来源出现位置都留一条记录。**同名、跨章重复、别名和同名异术分别判断。完全重复可共用正文，但每处来源仍指向同一正文标题；不能因为合并而丢失覆盖记录。
3. **禁用不等于漏收。**记录已转换、合并、禁用或尚缺依据，以及原因。用户要求全转换且禁止某法系时，可以把禁术单列；双法系中存在合法择一路径的条目，按其明文处理，不能只凭所在文件夹判禁用。
4. **先定共享口径，再逐项核例外。**六属性、有效技能、基础动作、通常威力和能耗可共用。逐术核攻击／豁免、选敌、动作特例、维持、能耗、材料、升级与叠加。遇到原文依赖物品、状态或造人规则，补齐必需定义；新增构造模板须标明只适用于该术，不能冒充已有全局建卡规则。
5. **相互引用必须可执行。**状态页写后果，感知页写定位能力，正文写目标与判定；不能用“按相应规则”掩盖库内缺失的规则。既有代表稿和新全量稿若有差异，在本次转换授权范围内核回原文，确定唯一当前正文。
6. **交付前比集合，不只比总数。**来源清单与覆盖表按“路径＋行号＋原名”逐项相等；每条覆盖记录都有真实正文标题；每个正文都进入目录；检查文件与锚点。分别报告来源出现次数、去重条目数、合法／禁用数、实际等级及额外配方，不把不同口径混成一个总数。

本次实例：24 份 D/C 源文件有 222 处收录，去重后 215 项，其中帝国合法 208 项、死灵禁术 7 项；合法项按实际等级分为 D 120、原生 C 88。《嗅识》《炽炎神域》需检查嵌入条目；《幻影面纱》所在目录与正文等级不一致；同一法术的跨章重复指向一份正文。这些是本次验收记录，后续批次应重建自己的清单，不硬编码这些数量。

多人分工仅在用户或适用指令授权时使用。若使用，先统一共享口径、规定文件归属和交付字段，再按互不重叠章节分配；汇总者检查跨章重复和口径冲突，不默认再开一轮全量评审。Sol 单独执行时也可按同样顺序逐章处理。

## 玩家正文与核算记录分开

**玩家正文**给完整资源名称、类型／等级、取得条件与 XP，以及适用的动作、消耗、目标／距离、持续、触发和效果。被动能力省略无关字段；“法术训练”“魔力增储”等名称后必须写实际收益。需要距离、路径、落点、是否替他人承受攻击或中断时点的效果，在条文本身说明。

复杂条文按施放方式、效果和进阶分段。玩家不用从预算表、相邻章节或旧稿拼出一句完整效果。可把真正共享的定义放在通则并链接；特殊规则在本术写全。正式版不混入“原有效果、参考、这次新增”等过程话语；会影响使用的未决项须在该条明确提示，不能为了纯净而隐藏。

**核算记录**单列原文路径／阶段、规则身份、本批适配、完整近例、预算和 XP 依据、未决项。用户指定不计预算的 NPC 自动辨识等福利也记清适用范围；不扩成玩家通用福利。需要把预算贴在同一答复时，放在正文之后。

**保存位置**遵守本库分工：原文在 `content/`，方法在 `authoring/`，已整理资源在 `resources/`，工作产物通常在 `outputs/`。`outputs/` 默认被 Git 忽略；需要独立迁移的指导经验必须留在受版本管理的文档，不能只链接被忽略的输出或旧聊天。用户要求收库时，再整理对应资源和依据；要求清理草稿时，仅清理确认由本任务生成且已被定稿替代的稿件，保留来源和必要核算，不顺带删除无关文件。

## 一次交付检查

- 核心效果及指定骨架保留；通用身份覆盖代表岗位；没有新增未授权的设计禁令。
- 每个能力都有可执行效果，距离、动作、持续、消耗及解除条件无矛盾。
- 各阶增量、树入口、属性投入、重复税和实际估价分别对账；没有凑数效果或假满额。
- 本体加成确实作用于配套；NPC 特例与普通资源区分；没有凭资格免费加级。
- 来源、规则优先级、本批适配与单项裁定可辨；XP 类型和学习版本无混淆。
- 批量任务逐源无缺漏，合并和禁用有记录；目录文件及锚点可达。
- 已知错误已在授权范围内修正；留下的是具体未决问题，没有把待核项宣布通过。
- 交付一份当前正文及必要依据；报告真正完成的检查，不声称已实战平衡或已节省特定 token。

新经验优先补充已有对应条目，只有新的失败类型才增加一条；不要把指南堆成每次必须通读的事故流水账。

## 可直接交给 Sol 的请求

> 仅用本库和本次需求执行：〔填写任务、等级、禁用项与保留范围〕。先读 AGENTS.md 和 authoring/README.md，按 authoring/lessons.md 的最短流程执行，只补读相关规则、特性和少量完整近例。修订保留指定骨架；转换保留原文效果并明写融合差异，批量任务先建逐源清单。容量、实投估价与 XP 分开核，不凑效果、不自造统一强度上限。交付可直接使用的玩家正文和分开的核算记录；确定错误直接修正，只有资料无法解决且实质影响结果的歧义才询问。完成一次针对性自查，输出到 outputs/ 并给出入口和实际检查结果，不依赖旧聊天，不自动提交或推送。
