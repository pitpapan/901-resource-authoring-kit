# 901 资源撰写入口

本目录与库根的 `content/`、`indices/`、`rules/`、`tools/` 一起复制，即可在别处使用。这里的卡片是检索与写作参考，不新增规则权威、审批程序或引擎接口。先读[撰写指南](guide.md)，按需要再读[常用规则卡](common_rules.md)、[特性速查](traits.md)与 2—3 张[定标样板](samples.md)。样板是 RE 原文比较材料，不代表 901 已采用，也不是质量金标准。

独立执行的具体经验见[操作指南](lessons.md)：先看最短流程，再按任务补读设计核价、规则转换或批量验收段落，不必每次通读所有经验。它同时提供可复制的 Sol 启动请求；不依赖旧聊天或工作目录中的历史输出。

续写已有系列先查[已整理资源](../resources/README.md)。帝国法师及通用法术已收库；使用其正文和本批通则，按需查核算。原书 CLI 索引保留来源身份，不混入这些改编条目。

## 一批资源的最短流程

1. 用[需求简表](brief-template.md)明确用途、对象、类型、强度上限和风格。能力组先依[指南](guide.md)说明训练内容、适用岗位和各阶收益，再分配预算；修订时先确认保留的原稿骨架。每阶用于强化属性的预算最多为2个同级特性，不要求用满；常规攻防与被动训练可作为本体。D/C 等原书等级不能直接等同某世界的战力档。
2. 先查相关规则与特性明文；表中没有直接条目的任何机制，都按[样板检索流程](calibration.md#按机制寻找样板)寻找完整近例，不限于成长加值。用机制与近义词跨类别检索，优先机制接近的同阶、低阶样板，再按需交叉比较高阶资源；不要求原型逐字相同。先读少量相关阶段，复用证据，不通读全库。
3. 写完整的玩家资源正文，另列简短的原文比较、预算和价格依据；名称不能代替效果，不把过程说明塞入正式条文。有类比组件时按[类比核算](calibration.md)对照完整原型，不从目标总额倒填组件价格。在核算记录中区分原文、901 已采用、原创候选及本批适配；会影响使用的未决项仍须在正文提示。
4. 核前提、动作、消耗、持续、叠加、进阶增量或替换，以及人物取得与引擎支持边界；分别检查容量算式、属性投入上限、组件估价、组合后的实际收益。复杂动作或协同效果用一个短场景检查即可，不强制常规训练增加新动作。未定标组件不能因总数相等或标了“候选”就算通过，不补造来源或 901 Canon。

修订和转换沿用这四步，只处理授权范围。批量转换先按[逐源覆盖流程](lessons.md#批量转换怎样保证不漏)建清单，共用定义只核一次，逐条检查特例。确定错误直接修正；只有资料无法解决且实质影响结果的歧义才询问，不为普通修正增加审批步骤。

从**库根目录**运行本地检索命令，搜索只定位，须回看命中原文前后段：

```powershell
python -X utf8 tools/library.py cards CR-04 TB-01 S-01 S-08
python -X utf8 tools/library.py search 剑盾战斗 --kind rules --limit 3
python -X utf8 tools/library.py read 'content/RE/01_rules/01_建卡与属性/战斗专长.md' --start 178 --lines 20
```

检索默认排除待重置、已移除和施工条目；明确研究旧例时才用 `--include-legacy`。机器片段、别名与标签只帮助找出处，不能证明语义匹配、完整前提或采用状态。

可直接复制给 Sol 的启动请求：

> 请仅用本库和本次需求〔填写任务与保留范围〕，按 `AGENTS.md`、`authoring/README.md` 及 `authoring/lessons.md` 的最短流程完成。按需读取规则、特性与完整近例，交付效果完整的玩家正文及分开的核算依据；确定错误直接修正，批量任务核逐源覆盖。完成一次针对性自查，写入 `outputs/` 并给出入口和实际检查结果，不依赖旧聊天，不自动提交或推送。

常规撰写可由 Sol 独立完成；来源冲突先查相关原文，能依规则优先级和上下文解决的直接处理并记录依据。仍不能解决的具体缺口如实保留，无需为每份草案另做高成本重写。可迁移的方法与指导写入 `authoring/`；`outputs/` 默认被 Git 忽略，不能作为独立库必需的隐含依赖。
