# 类比预算核算

这是撰写与自查方法，不是新特性价表、901新村规或额外审批流程。只检查本批涉及的机制，按下列流程定点取材，不通读全库。常用短卡为TB-01、TB-05、TB-06、TB-09、CR-09、T-23、S-09。

## 按机制寻找样板

**特性表没有直接条目的任何机制，都可以寻找同类资源作类比。**这不限于成长型加值，也包括范围与选敌、动作替代、触发与反应、位移、治疗、防护交互等。表中缺项不等于机制不存在、必须升阶或不能估价；名称、题材不同的资源也可能是合适样板。

1. **先确定查什么。**将效果拆成实际机制，写清触发、作用对象、结算阶段及关键参数；先查相关规则和特性明文，区分已有明价、类别固有性质与需要类比的增量。另核目标模板、树入口和实际动作／能耗／冷却调整；容量只供最后对账，不能决定该机制应值多少。
2. **按机制与近义表述定点搜。**先取相关卡片和[按问题索引](../indices/mechanisms.md)，不足再用 `tools/library.py search` 定位原文。检索“替代／代替”“只影响敌人／排除友军”“等同技能／技能等级”等实际措辞，跨能力组、技艺、能量、专长等类别寻找；不要只搜招式名、题材或整句原文。命中片段只用于定位，须回看相应完整阶段。
3. **优先比较机制接近的同阶、低阶样板。**先读1—3个强相关近例，核该阶段等级、原价、明示特性分配、前置购买、动作、能耗、次数／冷却、持续、叠加和捆绑收益；机制和条件的可比性优先于等级。高阶资源可交叉比较，但高阶整包包含某效果，不证明该效果本身须高阶。也不只挑最便宜或已移除的旧例；默认沿用检索工具对旧例的排除。
4. **比较实际差异，再给候选估价。**说明本稿保留、移除或放宽了什么，以及对收益和代价的影响；综合特性明文与完整近例判断。无需逐字同构，也无需每个捆绑组件都有独立售价；可以作有依据的类比，但不能把任意拆分伪称明价。固定值与成长值、本人和盟友、单体和范围、固有性质和额外保护、PHB／RE／901版本分别核对，不能仅凭相似名词套价。
5. **只补查具体缺口。**首批只命中高阶或条件不符的样板时，换近义词、资源类别或相邻机制再定点查找，并留意低阶完整阶段；不要据第一轮结果直接认定过强或无价。证据足以解释估价就停止扩搜；仍不能约束的部分列明具体缺口，不无限读库，也不因没有完全相同原型而拒绝全部类比。
6. **留下可复用的短记录。**按下表记录库内相对路径、阶段、支持的判断、差异与明价／类比／未定标身份，同批复用已有证据。分别报告估计投入、模板容量与XP依据；不从剩余容量倒推价格，也不为方便定价改动用户要求保留的效果。

例如，“等于技能／属性成功的加值”只是这一流程的一种应用：可比较[新格拳](../content/RE/02_resources/能力组/近战类型/肉搏类型/新格拳.md)的C阶多重格挡、[三刀三剑](../content/RE/02_resources/技艺/技巧/近战类型/武器技巧/三刀三剑.md)的C阶一剑藏空，以及[剑气](../content/RE/02_resources/能量/剑气.md)的D阶智剑平八方。它们分别提供技能关联防御或传奇属性关联收益的近例；仍须读完整成本和收益，不能将这些整包改写成通用组件价表。

## 一项效果怎样算有依据

先按[指南](guide.md)确认训练用途、岗位收益及修订时保留的原稿骨架；再核三件事：**模板有多少容量、效果实际值多少预算、与本体组合后增加什么收益**。另将 XP 模板价与实投估价分开写；算式相等只回答容量问题，不能证明用途合适，未用满也不自动要求填额或按比例减价。常规数值、被动训练与熟练度成长本身可以提供价值，无需为通过核算强造新动作。

每项类比留一条简短证据记录：

| 草案效果 | 原型与原文行段 | 原型完整成本和效果 | 本稿差异 | 核算结论 |
| --- | --- | --- | --- | --- |
| 写触发、目标与实际结果 | 库内相对路径、资源阶段 | 前置购买／资格、动作、能耗、次数／冷却、持续、叠加及捆绑收益 | 包括移除代价、改变武器、本人改盟友、多目标、常驻化 | 明价／有界类比／未定标；指出具体依据或缺口 |

- **明价**：特性表或明确拆账判例支持该组件与相同适用条件。跨级和重复投入仍须算数值税。
- **有界类比**：保留原型整套效果、关键条件和成本，或用直接相关近例解释差异；写清强弱方向与估价理由。没有独立单价不等于不能类比，多个相近资源的一致分配可以支持候选估价，见S-10。专长第三级的3D是该级整套容量，不能任意拆成若干已知单价；移去前置购买后也不能声称完全等价，但须同时比较新资源的取得成本，不能只因前提不同就拒绝估价。
- **未定标**：原型仅部分相似，无法解释拆分、扩展或成本变化。可以保留候选，也可换成有依据的效果；不得只加“类比”二字就宣称满预算或核算通过。

目标数加一、转交盟友、整轮压缩成标准动作、取消能耗，没有通用“各1特性”的默认价格。缩短射程或增加条件也不自动兑换特性补偿。不要从“还差2D”倒推出某功能正好2D。

给出预算区间时，两端同样须有原型或明确比较依据。自行选取的“试算1—2D”可以作为假设展示，但不能称为已受证据约束的估价区间，也不能据此证明装入或超出容量。无法约束的增量可暂用变量记录，写明成立所需的总预算条件；不把一个未知单价换成两个未知端点。

**来源容量与目标容量分开记。**独立技艺的原型按基础3特性比较，已付入口下的树中技艺有4特性容量。把独立3D原型搬进4D位置，不会使原效果自动值4D；剩余1D须有真实新增效果与依据。扩大新条目的容器或给原效果增加限制，都不是效果升值的理由。

**模板基础不等于最终容量。**另核技能树、动作、能耗、冷却等有原文依据或用户指定的调整，不把独立基础3特性误作所有独立资源的最终上限。[数值类特性](../content/RE/04_traits/可以确认的特性/数值类特性.md)第78—84行明确4AP补一个次级特性、6AP补一个同级特性；[RE白刃格挡](../content/RE/01_rules/02_战斗与动作/防御类动作.md)第29—33行为4AP，[901动作映射](../rules/901-core-rules-v0.1.md)第4节将4AP映射为移动动作。原书动作名称不能覆盖AP数值：C级在适用该动作补偿时为3C＋1D，不能仅因原书称“标准动作”就按6AP加到4C。用户为具体稿件另定4C时，采用值与原表结果分列，不扩成所有移动动作资源的通则。共同支付一次动作的整组收益只核一次补偿，不能逐组件重复领取。

**可变加值优先查杠杆与同类成长资源。**“等于某技能等级”“等于属性传奇点／自动成功”并不因可成长而自动失去估价依据。先读[数值类特性](../content/RE/04_traits/可以确认的特性/数值类特性.md)第45—48行的杠杆标尺，再找有特性分配的完整阶段；区分属性总值、传奇点、属性固定自动成功、技能附加成功与一次检定结果，说明901映射。可按触发、覆盖面、代价与叠加强弱作候选类比，不要求原型逐字同构，也不把所有捆绑效果一律拒绝估价；确实无法约束的增量才留待定。不得把RE参考技能6级当作901技能上限，或把角色当前数值当成资源永久上限。

## 类别固有性质与额外保护分账

遇到“不能降低”“不会失去”“无法被减免”等描述，先确定采用的版本、加值类别、结算阶段及具体攻击交互，不能只凭措辞把整句当作新免疫特性出售。按下表分别记录：

| 核算层 | 应记内容 |
| --- | --- |
| 数值收益 | 防御或吸收的数值、成长参数、触发与叠加；仍须按相应类型核价。 |
| 类别固有交互 | 某减防机制本来不作用于该类别的部分，记为“相对该类别基线无额外增量”，不重复收费；这不等于数值收益免费，也不等于该类别免疫所有减值。 |
| 额外保护 | 超出原有交互的保护，例如让一份偏斜不被整体防御减值削去，须独立比较完整近例；说明保护的是这份数值、全部防御还是伤害阶段吸收，不能相互代替。 |

偏斜是本次的具体核查例，不是全库新增免疫通则：

- [PHB 偏斜定义](../content/PHB/01_rules/能力模板本质价值类型.md)第119—120行保留独立偏斜类别。[RE 多次攻击](../content/RE/01_rules/02_战斗与动作/招式相关_留手_放弃防御_多次攻击_误伤.md)第29—33行只扣格挡、闪避和基础防御；[高速](../content/RE/01_rules/04_附录/物品关键字.md)第18行也有自己的目标清单。这些列举机制不含偏斜；按保留独立偏斜的口径，不受它们削减不产生额外收费。
- [RE 减值总则](../content/RE/01_rules/04_附录/本质与加值类型.md)第98—101行规定，未指明分项的防御减值作用于整体。保护某份偏斜免受这种减值，须与上述固有性质分开；明确无视该类别又是另一种交互。引用此规则须标明其 RE 原文身份及本次采用范围，不擅自扩成 901 全局决定。
- [RE 版本记录](../content/RE/00_meta/关于本书/2.5R_V1055.md)第15行把偏斜并入力场，而其[破甲](../content/RE/01_rules/04_附录/物品关键字.md)第24—27行可作用于力场。不能一面保留 PHB 偏斜，一面默用 RE 合并后的弱点，再为抵御这个新增弱点收费。
- [防御面特性](../content/RE/04_traits/可以确认的特性/乱七八糟的记录.md)第64—65行保护的是伤害减免、吸收、抵消、转化或硬度数值；不能把它直接当作防御 DP 抗削减的明价。

仅在确需展示额外收益时做一个短算例：其他适用防御5、偏斜8，遇到整体防御−10，通常剩3；若额外条款保护这份偏斜，则剩8。这次保护新增的是5点有效防御，不是再赠8点偏斜；仅针对基础／格挡的减防则不会因同一句保护重复获益。算例假定攻击满足该效果条件且未明确无视偏斜，不授予不存在的触发资格。

修订时若用户要求效果不变，只修核算说明，不为便于定价删保护、添能耗或设数值上限。最后分开报告：候选阶位／XP、模板容量、明价或有界类比的投入、仍待定标的增量；原价换算正确不等于组合预算通过，缺少精确明价也不妨碍有证据的完整类比。

## 本次军伍试写暴露的易错项

| 错误或混淆 | 今后核法与直接依据 |
| --- | --- |
| 通用军伍本体全部用于交替承伤、扩大接击距离和替人挡范围伤害，再靠弓手分支声称覆盖全兵种 | 这是主题范围失配。没有明文要求持盾，也不代表各岗位都能合理兑现本体价值；分别检查持盾、长兵、双手近战、弓弩的主要用途。共同训练与岗位专属能力分层，不能让射手等岗位额外买分支才获得适合自己的主要收益；也不能用“招牌要鲜明”迫使全员采用一个专门循环。见[设计检查](guide.md)。 |
| 移动效果把距离拆散在基础效果和预算加成中，只用“换位”概括 | 在效果正文直接写最终路径距离、是否随当时速度变化、双方各移多远及合法路径条件；例如半速经限定翻倍成为通常全速，应直接说明全速范围。这不是无限距离，也不是双方互换位置；实际范围仍须匹配用途，算式成立不等于设计合适。 |
| 把“攻击触及内所有生物”改成“只攻击敌人”，称为缩小范围或削弱 | 排除友军同时移除了误伤代价，是选择目标能力的增强，不能只比较目标数量。保留原型全部目标，或另找选择目标／排除友军的价格依据。近例为[巨武战士三级](../content/RE/01_rules/01_建卡与属性/战斗专长.md)第249—251行。 |
| 删除侧滑的特殊结算，改成走出触及就自动躲开，再称为删减 | [侧滑步](../content/RE/01_rules/01_建卡与属性/战斗专长.md)第643—648行明确通常不视为脱离攻击范围，远程另给闪避而非自动避开；移除例外后改套一般规则，可能实际增强效果。按具体结果比较，不以删除文字多少判断强弱。 |
| 从整套技艺删去格挡等收益、放宽剩余攻击加值的武器范围，直接沿用整套原价 | [双剑合璧](../content/RE/02_resources/技艺/组合技/组合技.md)第6—13行的独立3D包含共享格挡、指定剑法接攻与双手条款；它不是接攻＋6的独立单价。被移除和被扩展的功能须各列差异、找可比证据；相互一增一减不自动等价。 |
| D本体把6D全部换成属性，或将反对堆属性扩大成禁止常规攻防、先攻和豁免 | 用户指定每阶最多用2个同级特性强化属性，按预算而非属性点数计，不要求用满。合法数值与被动训练仍可构成本体；不强制每阶特殊招牌、新动作或非数值比例。见[TB-07](traits.md)与[指南](guide.md)。这是本库设计约束，不改写RE原文或901世界规则。 |
| 把一轮反馈扩写成永久审美禁令，随后整套重写用户要求保留的初稿 | 分清确定规则错误、证据不足与可选设计意见；依指定基线修正，保留训练类别和条目用途。原稿已正确处理的预算、距离或伤害归属无需重复“修复”。缺少价格证据时可保留功能并标缺口，不为方便定价换掉原本主题。 |
| 以T3为由把攻防统一压到＋3，或留下容量却报成满预算／已核定价格 | T档不换算固定数值上限。按模板、数值税、实际行动选择与同类资源比较；余量须列明，模板 XP 可作候选价但不等于逐项核价，也不按余量比例自动折价。见[TB-01／TB-03](traits.md)。 |
| 树入口计入本体普通额度，或漏算树下技艺的＋1 | 能力组普通效果与树入口分账；已支付入口的每项技艺分别3＋1。见[撰写规则](../content/RE/01_rules/03_其他规则/撰写规则.md)第32—44行。 |
| 把旧PHB装备破甲口径当RE破甲；把忽略硬度的表价当破甲表价 | 按来源分开；RE破甲不穿DR，破尽适用防御后的剩余破硬度。见[CR-09](common_rules.md)、[物品关键字](../content/RE/01_rules/04_附录/物品关键字.md)第24—27行。 |
| 没有效果或公式支持，却在文案声称提高伤害上限 | 分别写攻击DP、防御变化、武器伤害、伤害上限和实际伤害；不能互相代替。是否提高上限看其公式与真正改变的项，不以“破甲”一词推出。见[901核心§5](../rules/901-core-rules-v0.1.md)。 |
| 把弓箭手“射程翻倍＋破甲4”拆成随意单价，再凑4D | [弓箭手](../content/RE/01_rules/01_建卡与属性/战斗专长.md)第116—130行只适用弓，有属性、技能及专业前提；第三级为整套收益，一级取箭是另一阶段。跨武器或去掉前置购买要列差异，不能藏在预算等式中。 |
| 给急救“一轮压成标准动作”任意标2D | [PHB生存状态](../content/PHB/01_rules/生存状态.md)第63行只证明急救花一轮；[数值类特性](../content/RE/04_traits/可以确认的特性/数值类特性.md)的攻击动作减费不能自动推广为所有行动减费。本次定点核查未找到该急救压缩单价，应标未定；这不证明它永远不允许。 |
| 写“用盾遮挡”而不说谁被攻击、谁结算伤害 | 分清提供盾防、改换攻击目标、实际伤害分担；单体格挡与范围反射DP也分开。见[S-09](samples.md)；圣骑士整套能力不能直接拆为每功能1C。 |
| 把同一数值重复出售，或花满预算但组合后没有提升 | 算一次本体＋技艺＋同伴的实际结算。若已有攻击＋6，另一个不叠加的＋3或＋6不提高该数值；可以服务较低阶队友，但必须如实说明。明确可叠加时按表核价，闪避例外不扩成任意免费跨人授予。 |
| 为填额让负伤撤援背人反而更快、给急救附赠技能等级导致熟练医者不能学习，或给连击附带无关拔武器 | 先问附加效果是否服务原用途、前提是否合乎训练逻辑；无关或反直觉的组件删去，余量如实留下，再核独立购买价值与价格。这些是设计反例，不普遍禁止救援、技能赠级或拔武器。 |
| 把动作映射当动作赠送 | 4AP单次攻击的表价是2C；映射移动动作不包含位移。反射借盾是否另耗2AP、反射锁以及范围攻击的抵御方式都须写清。见[T-23](traits.md)、[CR-04](common_rules.md)。 |
| 因特性表有属性售价就默认任何属性包已适配901，或反过来认定能力组不能加属性 | [武士](../content/RE/02_resources/能力组/近战类型/武器类型/武士.md)第9—13行明确支持本体加属性。基础属性与资源加值仍须区分；叠加、派生及节点收益需有口径，模板价与普通属性升级价不能未经比较直接互换。见[TB-06](traits.md)。 |

## 交付前一次自查

核对用途、岗位覆盖、总容量、每阶属性投入上限与每项证据，检查叠加后的实际收益；写清适用的目标、动作、消耗、持续与结算时点，仅对复杂交互用短场景核算。将仍未定标的组件连同具体缺口列出，保留修订基线的功能；常规训练允许数值成长。无需增加多轮代理评审或程序测试。库的文档维护另运行现有完整性检查；它只验证文件与链接，不证明设计质量或资源平衡。
