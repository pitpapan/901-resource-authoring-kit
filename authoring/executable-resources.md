# 资源的阅读版与执行版

依据：用户2026-10-23要求，同一资源分别提供适合自然语言审核的版本和适合快速分类执行的版本。此格式不修改已采用规则，也不把资源定义当成人物已经取得。

## 两种表示与权威

- 阅读版仍放在 `resources/*.md`，完整写明收益、前提、动作、费用、时点、例外、持续、叠加及进化规则。核算与定价依据仍另列。
- 执行版放在 `resources/execution/*.rule.json`，以结构化字段表达同一条规则。不是把正文复制进JSON，也不是为每个资源生成一段独有JS。
- 两版共享稳定 `id` 和 `version`。执行版用 `reading.path`、`reading.sha256` 和条款标题指向确切正文。正文改动后，编译检查提示来源变化，重新核对有关条款。
- 已采用自然语言条文是语义依据；运行时只执行已核对的结构化条款。两者冲突属于版本/实现问题，不能由模型临场挑一个或悄悄改数。
- 阅读版和执行版是仅有的两份资源表示。给分类器的简短动作索引、给浏览器的ESM数据、世界书条目都是构建产物，不独立编辑。

## 执行版必须区分的内容

| 字段 | 内容 |
| --- | --- |
| `identity` | 名称、等级、类别、所属树、别名与适用版本 |
| `clauses` | 阅读版逐条款对应关系、通用效果/动作引用、执行状态 |
| `definition` | 引擎支持的效果声明；不得含JS函数或任意写存档脚本 |
| `actions` | 动作ID、显示名称、实际意图、动作费用、目标及所需选择，供分类器索引生成 |
| `inputs` | 类型明确的角色/目标/场景数据或玩家选择；指明提供者，缺失时只阻止相关动作 |
| `unresolvedRules` | 正文确实缺少或冲突的规则参数，附原文依据和推荐口径 |
| `implementationGaps` | 正文明确但尚未有完整执行支持的条款；这是开发工作，不交由用户补规则 |
| `verification` | 本版本核对和实际执行测试状态；禁止只因JSON可解析就标为可执行 |

一项资源可有多个动作和被动效果。共同前提只定义一次，单项例外写在相应动作。升级写明替换/保留关系，不把C版叠在D版上，也不把本体学习和子技艺学习混为一笔。

## 数值与结算

公式使用有限运算树：常数、明确存档/上下文读值、加减乘除、上下界和取整。运算器由JS实现，资源提供参数。不得把“智力乘威力”作为待模型自由解释的字符串，也不使用 `eval`。

效果声明包含作用对象、条件、加值类别和叠加方式；事件声明包含触发阶段、频率范围与消耗。阶段顺序由规则引擎统一维护，例如：攻击命中→正常减免→伤害转换→生命入账→伤后触发。共享2点忽略额度必须是一份共同预算，不能在DR、吸收、硬度各用2点。

复杂机制只有现有通用操作不足时才扩展执行器。新增的是可复用能力，例如“空槽才能接纳、伤害转计数器”，不是名为“澄心玄鉴”的另一套伤害引擎。资源负责选择伤害类型、上限、动作与条件。

## 三个例子

- 一理贯通：声明适用成长类型、每级/每门计费单位、减1与最低1、排除项；调用共享学习计价器。悟法XP另设用途与“一次足额、不可混付”的支付约束，不扩张减费范围。
- 风游涉世步：声明非重甲且合格能量池≥1时速度＋40，身法加值取最高；受击反射步是独立动作，完成合法五尺路径后才允许至多1点伤害转劲。
- 澄心玄鉴：声明智力＋学识＋匹配子技能/DC3的观察动作，成功建立有场景和迹象版本的目标记录；攻防加值查询该记录。无动作纳劲和迅捷借劲复用计数器/动作/伤害执行器。

## 人物卡与T0

人物成长卡引用资源ID、版本、阶位、取得来源和已选参数，不复制资源实现。模板的“可选/后期”身份不能变成取得事实。实际成长事务只变更本次获得的资源与派生变化，保留XP余额、伤势、能量当前值、库存、冷却和既有选择。模板不能整张覆盖T0。

## 编写顺序

先写/修订阅读版，按条款填写执行版，再检查对应关系与具体场面。明确规则直接结构化并实现；真正缺参数的集中列出。完成执行测试后再生成世界书、分类器索引和浏览器包。迁移过程允许明确标注未完成，但不得把“已索引”标为“已可自动执行”。

## 2026-10-24 已接入的共享接口

- `programs` 支持独立多次目标序列、玩家选项白名单、声明式分配总额及单项上限。输入来自有来源的实际计划；分类器只选择计划，不提交公式、骰值或效果补丁。
- `aura` 保存施放时公式值与选定目标，按实际位置／敌我关系更新成员；场外用 `ruleScene.spatial`，不能借用模板坐标。公式是否随属性变化重算的歧义仍在相应契约 `unresolvedRules` 中列出。
- `channel` 配合 `cast / maintain / release` 登记维持动作、首次费用、目标约束和专注复检。持续时间不自动生成维持费用；来源未要求的维持动作也不新增。
- `incomingHit` 是一次实际命中事件；可用近战条件触发反击，不要求已经扣除生命，也不因该攻击分段伤害重复触发。伤害触发的其他类型仍须分别接入，不能借该事件名宣称全部支持。
- 临时力量增益更新实际HP容量；撤除按已采用D11迁移既有B/L/A伤势，溢出升级，不删除伤害。状态中的 `resourceHealthBonus` 记录已计入的临时差额，存读档后不重复增加。属性伤害仍不擅自重排HP；基因锁力量只计一次。
- 效果、状态、触发器、领域和维持实例保存来源及执行版本；定义存在不等于持有。运行数据、分类器、六书候选分别核验来源与哈希，实际部署版本另行记录。

主库 `audit_execution_coverage.py` 比较全部阅读哈希、契约、生成定义和分类器内容；`verify_candidate.py` 核验六书及浏览器依赖闭包。二者都是本地一致性检查，均不能据此把资源标为 `runtimeFullyVerified` 或声称已经安装。

## 本轮新增接口与仍未完成的边界

- `counter` 只读写已存在的实际计数器；条件状态记录触发来源，恢复越过阈值后解除，后来普通消费到零不会重触发。阿撒托斯的诅咒已用此接口处理意志归零昏迷。
- `temporaryHealth` 保存每来源余额，重算与读档不回满；伤害按 A/L/B 优先吸收，不可避免伤害绕过。天堂之盾的硬度与余额绑定；天使之障壁的分配按受术者保存，离区暂停、返区恢复余额。跨来源并存的选择规则仍待裁定，当前拒绝并存冲突，不擅自相加或覆盖。
- 反射资源由声明的动作类型进入现有待定攻击窗口，支付能量、额外计数器费用与反应锁；待定攻击和支付结果可存读档。天堂之盾已有标准与反射两种入口。
- `weaponEffect` 绑定有来源的物品实例，换武器不携带该加值，实际转交物品保留附魔。武器拔取按实际存放位置和已取得即时备战计费；实际持物不是学习记录，不能授予模板成长。非自愿武器接触、护甲战斗穿戴及全部异类武器攻击路径仍有实现缺口。
- `dispel` 选择目标实际持续实例，保留施放等级，结束同一来源关联效果；受术者自行选择，有来源的计划保存选择者。领域成员单独解除后，刷新和读档不会重新赋予，新施法可重新纳入。有来源、等级及持续时间的状态已可解除，永久后果不随点数删除；明确不可移除的来源不被普通解除绕过。旧式无来源等级的计时效果、物件附魔目标与 A 以上版本未全部接通。
- `statusSource / consumeStatusSource` 按实际状态来源和来源人物选取可移除点数，不能跨来源取值或把不可移除点数用于增伤。燃尽复用这两个操作。

以上接口已有定向本地执行证据，不等于整份资源的全部等级、关键词与变体已验证；合同仍为 partial，实际安装版没有自动变更。

- `targetFacts` 校验有来源的目标资格及敌意等事实，不从姓名推种族，不接受模型提交效果数值；`sameSource: ineffective` 在真正受术者上检查同名效果。法术抑制的双类型免疫按声明比例减弱，法强归零阻止新施法；忽略临时增益不等于忽略减值。
- `attackResolved` 与“造成生命伤害”分开：下一次匹配攻击落空仍消耗附魔；命中后即使普通物理伤害被挡尽，附加能量仍独立结算。炽焰斩、致盲斩、激愤斩已迁移；物件与特殊免判定攻击路径仍明确列缺口。
- `loseAction` 直接扣指定尚未用的动作，否则保存到下一次实际行动；不会用标准动作替代损失，剩余标准仍能正常换移动。惊惧斩复用该操作，并在附加伤害后作意志豁免，实际受术者的心灵免疫照等级过滤。
- `afterLifeLoss` 由伤害结算提供实际来源、受害者、敌我关系和生命损失，源自多个段的同一事件共享触发额度；同次攻击的关联伤害完成后才分发。报偿的伤害明确 `noAttackSource`，保留资源来源但不形成再次反伤的攻击来源。普通武器、通用法术及已接线的NPC伤害入口可用；旧燃烧/流血聚合和特殊反射归属仍列工程缺口。
- 伤害入口可声明 `segmentMode: independent-types`：多个单类型独立流程各自完整防护并产生自己的伤后事件，同类型 A/L/B 分段仍共享防护。来源未要求此分法的旧 PHB 入口保留已采用分组，不能因数组出现多项便自动倍增触发次数。RE 伤害通则已规定同类伤型、额外伤害不递归及定值伤害不触发额外伤害；后续伤害订阅必须执行这些既有规则，不把它们列作缺参数。
- 伤害入口声明 `damageNature`，区分攻击、其他骰伤、定值、额外及反伤；未分类入口不能默认取得额外伤害触发资格。脆弱诅咒复用 `afterLifeLoss` 与 `perRound` 额度，按实际战斗轮/场外经过的六秒刷新，读档与重施不清空同轮已用额度。场外时钟由已有实际经过时间事务更新。
- 同一施法者重施不增加同轮次数，不同资源的额度分别保存。RE FAQ要求区分数值加值与伤害实例；用户已于2026-10-24明确采用：跨施法者同名脆弱/报偿按独立来源分别结算、额度独立；同施法者重施不重置已用额度。旧存档的 pending-cross-caster 策略按契约 triggerPolicyMigrations 迁移，仅改策略及记录采用来源，不重算威力或清空额度。每个触发器执行前重新取得当前人物状态中的实例，避免前一伤害事务复制状态后把后一个额度写进旧对象。原文依据和用户采用记录已经写入对应契约的 adoptedDecisions；这不等于完整验证。


## 普通动作、法术与资源共用程序入口

`definition.access: common` 明确普通动作无需学习；默认资源仍须真实取得。`basicActions` 将固定命令绑定到可信 `programs`，战斗不新增同名专用分支。阅读版 [普通动作](../resources/basic-actions.md) 与 [全力防御契约](../resources/execution/basic-full-defense.rule.json) 为已接入样例；它不改T0人物卡或已学资源。

同一 `effect` 支持两种公式时点：默认 `cast` 冻结施放参数；明确 `formulaTiming: live` 才按结算时上下文计算。`expiresOn.actions` 在成功支付相应实际动作后结束，失败请求、回合结束和普通移动不会自动当作标准动作。通用事实上下文提供基本防御、有效格挡、是否能闪避、范围豁免、实际可见枪械及效果标签；标签只来自当前有效效果。

全力防御通过配置赋予闪避、范围反射及可见枪械高速抑制；“防护”只声明对有效格挡和 fullDefense 标签的条件，同类力场取高；法师护甲的 `fallbacks` 在原防御类别已被更高值覆盖时，按该次攻击完整计算各备选，选一个较有利结果，不能同时叠加力场与抵消破甲。

临时生命 `damageFilter` 与能量抗力条件按真实伤型筛选；RE能量为纯能量、火、冷、电、腐蚀、音波、光能、神圣、亵渎，不能因旧内部 kind=energy 就吸收精神、力场或毒素。防护能量结界的 `refresh: maximum-remaining` 只比较新份额和当前剩余份额，不把旧容量已消耗部分复活；D/C反射额外意志分别2/6。

`effectUseBlock:<family>` 是按等级限制使用者的共享资格接口；次元锚声明 space。旧角色传送缺等级时只在实际需要比较限制时要求 `effectGrades.lower/upper: {grade, source}`。不能从名称或耗魔反推等级；不能把使用者限制扩成所有被传送者免疫。

武器实例的有来源 `grip` 与原本 `hands/size` 决定实际力量要求；不足按PHB减DP，弓同时减少最大射程与增加超射程减值。旧角色的弓参数不覆盖真实新武器。武器跨类型攻击与全部关键词仍未完成，这部分不能仅凭通用持握函数标为完整。

通用化的验收标准是“新增可表达特性只改契约和阅读版，不加特性同名JS分支”。新增基础机制时补共享原语、消费者和行为测试；缺少原语仍列 implementationGaps。当前仍存在旧角色专用分支，不能把已接入的接口描述成任意特性均已支持。

## 实际武器、伤害触发与能量池事务补充

实际武器的类型、技能、伤害严重度、力量要求、射程与伤害上限从物品实例和资源定义取得；跨类型时不沿用旧角色的剑/弓专用分支。弓的 `ammunition` 声明装填动作和实际箭数消耗，装填状态保存在该物品实例，转交/切换不会复制旧弓状态；未记录箭数不能生成箭。弃风的高速对实际持有人生效，同类取高；减防仍检查白刃资格。分类器显示实际武器/装填/箭数；T0面板不展示后期完整卡的硬编码被动说明。枪械、投掷的完整消耗与其他武器关键词仍未接通，明确报告实现缺口；同类型旧角色特例也尚未全部迁移。

`damage.unavoidable` 在统一伤害入口保留：直接记录实际伤势，绕过防护、临时生命、伤害转换，不消耗下一次纳劲声明，不触发唤醒、欲眠点数减少、伤害专注复检或伤后反应。混合事件分别累计全部伤势与有触发资格的实际损失；只有后者进入共享/延迟伤后事件。声明式 `damage` 操作传递该标志；不能仅在单个法术里免除防护。来源为 RE《规则术语解释》“不可避免”条款（131–135行），并非新增裁定。

`poolTransfer` 以现有明确分类的通用能量池为扣除对象，依据实际扣除量计算回复，钳制到真实余额和目标上限。不创建池，不把特殊池/计数器当成通用池；缺分类是实际状态资料缺口。选中的池为空时扣零，声明的池不存在时才用可信d10从通用池均匀随机选取；没有通用池则失效。计划 `poolChoices` 在每次生效时读取，持续专注不会把初次选择永久冻结。

`resourceDailyUsage` 按来源与实际 `dayId` 持久化实际回复量；回满溢出不计用量、读档不重置，经过分钟不自动推定游戏日期。解释器可表达“当前容量”或“当日首次固定”的明确规则，必须由可信契约提供采用口径，不能由分类器提交数值/策略。**吸取魔力与生命分流的当日容量时点、D/C共享额度仍待用户回答**；当前吸取魔力契约为 pending，涉及每日回复的执行会报告 RULE_UNRESOLVED，测试中独立提供的测试规则不表示项目采用。生命分流的伤势按A价治疗仍是另一个实现工作，不能列为缺参数。临时生命跨来源采用问题仍独立保留。


## 共享抵抗、效果等级与组件免疫（2026-10-24.3）

`save` 只取得一次目标的真实豁免结果；`resolve.kind` 可为 `roll`、`opposed`（声明 `active`）、`threshold`（声明 `dc`）、`subtract`（声明 `incoming / perSuccess`）。主动对抗相等按901已采用规则成功，但胜出数为零；固定难度和按成功数扣点不互相冒充。`resultAs` 公开结构化结果供后续条件/公式读取，普通 `as` 保留数值成功数兼容旧程序。

`status / damage.resistance` 引用已生成的抵抗收据，`kind: subtract` 使用明确的 `perSuccess` 扣点；`kind: resolved` 表示数值已由可信公式完成该次抵抗。收据绑定本次目标和组件，不能跨目标/组件借用；消费收据不会再调用状态默认豁免。恐惧术、虚弱诅咒、睡眠术、恐惧嚎叫、心灵震爆、灾祸术与魅惑人类已迁移相应结算。规则来源为各术维护正文、00-施法通则与901对抗规则，未新增平手重掷口径。
