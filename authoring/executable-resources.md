# 资源的阅读版与执行版

依据：用户2026-10-23要求，同一资源分别提供适合自然语言审核的版本和适合快速分类执行的版本。此格式不修改已采用规则，也不把资源定义当成人物已经取得。

## 两种表示与权威

- 阅读版仍放在 `resources/*.md`，完整写明收益、前提、动作、费用、时点、例外、持续、叠加及进化规则。核算与定价依据仍另列。
- 执行版放在 `resources/execution/*.rule.json`，以结构化字段表达同一条规则。不是把正文复制进JSON，也不是为每个资源生成一段独有JS。
- 两版共享稳定 `id` 和 `version`。执行版用 `reading.path`、`reading.sha256` 和条款标题指向确切正文。正文改动后，编译检查提示来源变化，重新核对有关条款。
- 已采用自然语言条文是语义依据；运行时只执行已核对的结构化条款。两者冲突属于版本/实现问题，不能由模型临场挑一个或悄悄改数。
- 阅读版和执行版是仅有的两份资源表示。给分类器的简短动作索引、给浏览器的ESM数据、世界书条目都是构建产物，不独立编辑。

## 执行版必须区分的内容

| 字段 | 内容 |
| --- | --- |
| `identity` | 名称、等级、类别、所属树、别名与适用版本 |
| `clauses` | 阅读版逐条款对应关系、通用效果/动作引用、执行状态 |
| `definition` | 引擎支持的效果声明；不得含JS函数或任意写存档脚本 |
| `actions` | 动作ID、显示名称、实际意图、动作费用、目标及所需选择，供分类器索引生成 |
| `inputs` | 类型明确的角色/目标/场景数据或玩家选择；指明提供者，缺失时只阻止相关动作 |
| `unresolvedRules` | 正文确实缺少或冲突的规则参数，附原文依据和推荐口径 |
| `implementationGaps` | 正文明确但尚未有完整执行支持的条款；这是开发工作，不交由用户补规则 |
| `verification` | 本版本核对和实际执行测试状态；禁止只因JSON可解析就标为可执行 |

一项资源可有多个动作和被动效果。共同前提只定义一次，单项例外写在相应动作。升级写明替换/保留关系，不把C版叠在D版上，也不把本体学习和子技艺学习混为一笔。

## 数值与结算

公式使用有限运算树：常数、明确存档/上下文读值、加减乘除、上下界和取整。运算器由JS实现，资源提供参数。不得把“智力乘威力”作为待模型自由解释的字符串，也不使用 `eval`。

效果声明包含作用对象、条件、加值类别和叠加方式；事件声明包含触发阶段、频率范围与消耗。阶段顺序由规则引擎统一维护，例如：攻击命中→正常减免→伤害转换→生命入账→伤后触发。共享2点忽略额度必须是一份共同预算，不能在DR、吸收、硬度各用2点。

复杂机制只有现有通用操作不足时才扩展执行器。新增的是可复用能力，例如“空槽才能接纳、伤害转计数器”，不是名为“澄心玄鉴”的另一套伤害引擎。资源负责选择伤害类型、上限、动作与条件。

## 三个例子

- 一理贯通：声明适用成长类型、每级/每门计费单位、减1与最低1、排除项；调用共享学习计价器。悟法XP另设用途与“一次足额、不可混付”的支付约束，不扩张减费范围。
- 风游涉世步：声明非重甲且合格能量池≥1时速度＋40，身法加值取最高；受击反射步是独立动作，完成合法五尺路径后才允许至多1点伤害转劲。
- 澄心玄鉴：声明智力＋学识＋匹配子技能/DC3的观察动作，成功建立有场景和迹象版本的目标记录；攻防加值查询该记录。无动作纳劲和迅捷借劲复用计数器/动作/伤害执行器。

## 人物卡与T0

人物成长卡引用资源ID、版本、阶位、取得来源和已选参数，不复制资源实现。模板的“可选/后期”身份不能变成取得事实。实际成长事务只变更本次获得的资源与派生变化，保留XP余额、伤势、能量当前值、库存、冷却和既有选择。模板不能整张覆盖T0。

## 编写顺序

先写/修订阅读版，按条款填写执行版，再检查对应关系与具体场面。明确规则直接结构化并实现；真正缺参数的集中列出。完成执行测试后再生成世界书、分类器索引和浏览器包。迁移过程允许明确标注未完成，但不得把“已索引”标为“已可自动执行”。
