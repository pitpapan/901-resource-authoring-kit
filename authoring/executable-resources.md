# 资源的阅读版与执行版

依据：用户2026-10-23要求，同一资源分别提供适合自然语言审核的版本和适合快速分类执行的版本。此格式不修改已采用规则，也不把资源定义当成人物已经取得。

## 两种表示与权威

- 阅读版仍放在 `resources/*.md`，完整写明收益、前提、动作、费用、时点、例外、持续、叠加及进化规则。核算与定价依据仍另列。
- 执行版放在 `resources/execution/*.rule.json`，以结构化字段表达同一条规则。不是把正文复制进JSON，也不是为每个资源生成一段独有JS。
- 两版共享稳定 `id` 和 `version`。执行版用 `reading.path`、`reading.sha256` 和条款标题指向确切正文。正文改动后，编译检查提示来源变化，重新核对有关条款。
- 已采用自然语言条文是语义依据；运行时只执行已核对的结构化条款。两者冲突属于版本/实现问题，不能由模型临场挑一个或悄悄改数。
- 阅读版和执行版是仅有的两份资源表示。给分类器的简短动作索引、给浏览器的ESM数据、世界书条目都是构建产物，不独立编辑。

## 执行版必须区分的内容

| 字段 | 内容 |
| --- | --- |
| `identity` | 名称、等级、类别、所属树、别名与适用版本 |
| `clauses` | 阅读版逐条款对应关系、通用效果/动作引用、执行状态 |
| `definition` | 引擎支持的效果声明；不得含JS函数或任意写存档脚本 |
| `actions` | 动作ID、显示名称、实际意图、动作费用、目标及所需选择，供分类器索引生成 |
| `inputs` | 类型明确的角色/目标/场景数据或玩家选择；指明提供者，缺失时只阻止相关动作 |
| `unresolvedRules` | 正文确实缺少或冲突的规则参数，附原文依据和推荐口径 |
| `implementationGaps` | 正文明确但尚未有完整执行支持的条款；这是开发工作，不交由用户补规则 |
| `verification` | 本版本核对和实际执行测试状态；禁止只因JSON可解析就标为可执行 |

一项资源可有多个动作和被动效果。共同前提只定义一次，单项例外写在相应动作。升级写明替换/保留关系，不把C版叠在D版上，也不把本体学习和子技艺学习混为一笔。

## 数值与结算

公式使用有限运算树：常数、明确存档/上下文读值、加减乘除、上下界和取整。运算器由JS实现，资源提供参数。不得把“智力乘威力”作为待模型自由解释的字符串，也不使用 `eval`。

效果声明包含作用对象、条件、加值类别和叠加方式；事件声明包含触发阶段、频率范围与消耗。阶段顺序由规则引擎统一维护，例如：攻击命中→正常减免→伤害转换→生命入账→伤后触发。共享2点忽略额度必须是一份共同预算，不能在DR、吸收、硬度各用2点。

复杂机制只有现有通用操作不足时才扩展执行器。新增的是可复用能力，例如“空槽才能接纳、伤害转计数器”，不是名为“澄心玄鉴”的另一套伤害引擎。资源负责选择伤害类型、上限、动作与条件。

## 三个例子

- 一理贯通：声明适用成长类型、每级/每门计费单位、减1与最低1、排除项；调用共享学习计价器。悟法XP另设用途与“一次足额、不可混付”的支付约束，不扩张减费范围。
- 风游涉世步：声明非重甲且合格能量池≥1时速度＋40，身法加值取最高；受击反射步是独立动作，完成合法五尺路径后才允许至多1点伤害转劲。
- 澄心玄鉴：声明智力＋学识＋匹配子技能/DC3的观察动作，成功建立有场景和迹象版本的目标记录；攻防加值查询该记录。无动作纳劲和迅捷借劲复用计数器/动作/伤害执行器。

## 人物卡与T0

人物成长卡引用资源ID、版本、阶位、取得来源和已选参数，不复制资源实现。模板的“可选/后期”身份不能变成取得事实。实际成长事务只变更本次获得的资源与派生变化，保留XP余额、伤势、能量当前值、库存、冷却和既有选择。模板不能整张覆盖T0。

## 编写顺序

先写/修订阅读版，按条款填写执行版，再检查对应关系与具体场面。明确规则直接结构化并实现；真正缺参数的集中列出。完成执行测试后再生成世界书、分类器索引和浏览器包。迁移过程允许明确标注未完成，但不得把“已索引”标为“已可自动执行”。

## 当前声明式接口补充（2026-10-24）

- 编译产物保留合同的规范 `identity/tree`、`reading` 与 `verification`。学习报价不能把已知外树资源改报为观澜树；本树减费与悟法XP分别核验。合同含未决规则时不得标记完整可执行。
- `programs` 的键是登记操作选择器；例如透特之咏的神秘／学识／科学、灼热之痛的剧痛／仇恨分别登记。分类器只选已有键，不提供公式或效果数值。`choices` 为契约枚举，缺失或未登记的选项在扣费前阻止相关操作。
- `repetition` 用 `count` 表示固定次数，或 `maximum` 表示可选上限；实际目标列表逐次指定，允许重复同一目标。`extraCost` 对第一枚以后的每枚计费，`extraCondition` 核验多枚前提。动作及共享冷却仍只付一次，各枚独立攻击、伤害和防护结算。
- 效果条件里的 `snapshot` 在施放时固化选项或施术者ID，`context` 留给后续实际判定。例如解析抗力只削减对原施术者的抗力；不能扩散给他人，也不能把负抗力变成额外威力。`inspect` 仅读取声明的现有资源统计，不授予加值。
- 临时属性效果写入与到期时重算有配置人物的派生值。生命容量缩小时复用已有PHB伤势槽溢出规则，不清除伤势、补满能量或重置XP。旧比较面板已计入的收益通过匹配版本的 `legacyProfiles` 替换，不能与新资源重复计入。
- 以上是开发执行接口。合同的 `runtimeFullyVerified=false`、实现缺口和未决项继续随分类器及六书投影公开；生成或通过本地检查不等于已经安装到实际聊天。

## 显式程序政策接口（2026-10-25）

`definition.programs`可用以下附加字段声明通用执行政策；现有schema允许这些program字段，无需另建格式。缺省不改变原D/C程序路径。

- `executionPolicy`：用`ranks`明确允许的等级、等级数值和固定威力；`requiresCaster:false`只免施法职能，不免成分、实际取得版本／来源／采用记录或`requiredSubskills`资格。`pool`可声明`selection:"learned-choice"`、取得时选择字段和实际能量类别；须由已保存的池类型或有来源的取得资格证明，普通通用池不能自动视为魔力。
- `integerInputs`：登记玩家可选整数的默认值、最小值及有限公式上限；`maximumSource:"highestCasterLevel"`只读真实施法者记录。`allowMinimumWithoutMaximum`允许无增幅的基础用法不依赖尚缺的增幅等级。不得接受分类器提供P、治疗数或任意效果公式。
- `targetPolicy`：`touch`核对实际触及和距离，自身不额外索取外部触距；`living`同时核对生命类别和实际伤势死亡，主持计划不能覆盖已保存的死亡或非活物身份。声明政策的治疗程序在支付前验证`healOrder`只含不重复的A/L/B，治疗仍调用共用`healWounds`，不另建专属治疗器。

这些字段须经具体执行场景测试后才能进入动作白名单。证明应固定program／action、契约版本、阅读及共享规则hash和相关执行代码hash；schema通过、program存在、某个cast通过均不等于学习事务、整段条款或全部候选已实现，也不表示已部署。


## 显式学习政策接口（2026-10-25）

`definition.learning.baseXP`为固定学习原价；`learning.policy`可显式声明允许的`grades`、`requiresCaster:false`、`requiredSubskills`，以及`pool:{choice:"magicPool",kind:"magic"}`。这是现有`growth-pricing`／`resource-acquisition`的可选政策：未声明者继续使用原D/C资格与取得逻辑。候选政策的报价须登记`contractVersion`，与当前合同完全相同，并沿用已有`adopted/source/actorIds/requirementsMet`事实；分类器仍只选择`action:"resource"`、`offerId`及可选`paymentId`。

主持在报价的`acquisitionChoices.magicPool`选择实际已有池。池已有`kind:"magic"`时直接核验；旧卡未记类型时，须在该报价的`acquisitionQualifications.energyPools[池名]`登记`{kind:"magic",source:"实际确认来源"}`，不能因`generic:true`而视为魔力。咒法等专业核对人物实际技能。每次付款前都复核资格、池与当前版本；分期同时锁报价及合同价格、资格与身份，旧合同或旧分期签名不能绕过新政策。付清才记录取得版本、采用／来源、选择与核验过的资格，不创建能量池、不回能、不授予施法职能。

计价、支付和保存复用现有事务。资源所属树仍取合同身份，外树无级法术不因此获得观澜本树减费或悟法XP支付资格。学习政策须独立测试并固定价格／资格政策、版本、正文／共享hash及相关计价、取得、持久化代码hash；施法证明不能代替学习证明。候选编译可以导出已验证政策，但报价仍由主持逐项登记，编译和注册定义均不授予实际人物资源。
