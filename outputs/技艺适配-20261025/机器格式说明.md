# 技艺机器格式 · 候选接入包

遵循仓库[阅读版与执行版规范](../../authoring/executable-resources.md)及[`901-resource/1` schema](../../resources/execution/resource.schema.json)。机器规则唯一可编辑来源是[execution/contracts](execution/contracts)中的268份`.rule.json`；阅读正文不变，生成ESM、覆盖与分类器索引均不可独立编辑。本包未安装到主库、分类器、人物或存档。

## 覆盖与当前执行程度

- 来源覆盖192：141个非通用魔法来源对应141份资源／汇编契约；27个新增通用魔法来源的134处定义合并为127份契约。24个D/C来源的222处记录，按[reuse-map.json](execution/reuse-map.json)复用215个正式契约ID，不复制正式实现，保留7个帝国课程禁用术的原身份。禁用作用域仍为帝国法师课程。
- 268份契约包含951个锚点单元；单元是条款定位，不等于951项可购买资源。学习候选价、阶段、动作组合、明确成本／时长／冷却、前提原子、范围公式及来源关系已经结构化；字段各自有`semanticStatus`。非标准消耗、复杂条件、承继与跨条款关系仍存在未编码部分，因此**尚未完成全量语义编码**。
- “直感”四阶段的攻防洞察部分已有4个测试范围、标准`definition.effects`中8条效果；其验证范围仍仅为`collectEffects/stackEffects`。另已完整接通治疗微伤的`cast`使用动作，契约版本为`2026-10-25.machine.4`，通过现有kit分派、通用program与healWounds结算真实状态；另有独立学习证明：已登记候选报价可经现有通用学习事务支付3XP、记录取得，再施法。
- **主动动作白名单为1，完整自动执行契约仍为0。** 其余489条动作意图保留blocked，950个未完整执行的条款进入blocked索引。治疗微伤cast不再同时列为blocked；学习入口另经独立证明开放，必须有主持逐项登记的真实候选报价；其余资源的取得事务未随之实现。不能因为JSON合法、已有参数、人物`learned=true`或分类器找到名称，就执行这些条款。

## 契约与ID

顶层沿用`schemaVersion/id/version/identity/reading/definition/clauses/actions/inputs/unresolvedRules/implementationGaps/verification`，没有第二套顶层schema。`identity.adoptionStatus="candidate"`，不推定已经采用、已学会或付XP。

`id`是固定资源身份，`version`是机器版本；条款另有稳定ID及阅读锚点。`reading.sha256`锁正文，条款`sectionSha256`锁具体段落，`sourceReferences`锁原书路径／SHA256／行段。`identity.sharedDependencies`同时锁共用判定、两篇必要依赖、制符表、901核心及schema；任何共享规则变化都会使编译报过期。

`definition.effects`、`definition.programs`仍为现行声明式接口。复杂条款的进度材料置于`definition.authoringOnly`：学习与升级对象、typed参数、已识别机制片段、未编码条件以及条款对应。**现有JS不解释这些authoringOnly字段**，不能把片段标成已实现操作；其中`runtimeSlices`只保存标准effects的索引和测试范围，不复制另一份效果规则。

公式只使用有限AST，没有`eval`或模型自由公式。范围里的智力／感知／力量使用typed有效属性`context.INT/PER/STR`，不代换成基础属性；L与A仍独立。输入明确区分存档、玩家选择、主持事实；缺少实际目标或资格只阻止相关操作，不升级为“规则缺参”。未枚举的选择不由模型补数。

`unresolvedRules`仅有原先U01–U04四个真实缺口，保持原处理；尚未实现的前提、动作和效果列入`implementationGaps`，是开发工作。已知规则没有因为“尚未编程”而要求用户裁定。

## JS与分类器生成物

| 文件／导出 | 用途及边界 |
| --- | --- |
| `generated/resource-data.mjs` → `RESOURCE_DATA` | 含测试证据仍有效的8条被动效果、治疗微伤`cast`及独立已验证学习政策，共2个资源定义。 |
| `generated/resource-action-index.mjs` → `RESOURCE_ACTION_INDEX` | 真正已验证动作白名单，当前仅治疗微伤`cast`；另附其`learning`选择器指向已有`action:resource`报价入口。 |
| `generated/resource-blocked-index.mjs` → `RESOURCE_BLOCKED_INDEX` | 可用于名称定位和后续实现规划；`operation=null`、`mayExecute=false`，不得发执行请求。 |
| `generated/resource-contract-index.mjs` → `RESOURCE_CONTRACT_INDEX` | 全量候选身份、typed字段、条款去向、缺口与学习资料；供检索／审阅，不是执行白名单。 |
| `generated/coverage.json` | 覆盖统计、正式ID引用、契约指纹和已验证范围。 |

本包的候选动作白名单只约束新增候选；24来源的正式复用项继续沿正式契约与正式动作索引的实际验证状态，不被本包重新封禁或自动增补。

现引擎的`resource-program.mjs`固定D/C等级与P、支付池仅允许imperial/guanlan、攻击固定智力及施法语境、部分重复效果会刷新旧期限。其缺省路径仍为原D/C行为；本轮为显式政策补了无级程序、已取得魔力池资格、有界整数增幅、触及活物与支付前验证，仅治疗微伤获得执行证明。它仍不完整支持本批其他B/A/S、无级法术和普通武技。对应grade、pool、attack、refresh以及资格事务缺口逐条保留；本轮只补上述通用政策支持，不注册其他未验证operation。

已验证被动也须有**该阶段独立取得记录**。每条效果的`when`核验阶段`learned/version/grade/adoptionStatus/qualificationVersion`及所有前置阶段，汇编总开关不会授予全阶。`qualificationVersion`固定对应正文和共享规则版本；应由真实取得事务在核对资格后登记，分类器不得写入。这四个被动阶段尚无已验证取得事务；编译不补造其取得记录。治疗微伤的独立学习政策沿现有通用事务执行。

## 重建与验证

从仓库根目录运行：

```sh
python outputs/技艺适配-20261025/compiler/compile.py
python outputs/技艺适配-20261025/compiler/compile.py --check
python outputs/技艺适配-20261025/compiler/verify.py
```

第一条仅重建本候选目录生成物。后两条只读：校验现有schema、268份正文与原书／共享hash、192来源集合、正式复用、条款对应、生成物确定性、4未决及127术学习／能耗／持续字段，再本地导入4个ESM并复跑实际JS的54个断言和11组原句语义回归。测试不写人物或注册表，不联网。具体修正见[规则检查记录](规则检查-20261025.md)；这些检查不代表所有条款已完整编码。

`execution/runtime-verification.json`记录这8条效果的精确指纹与执行器SHA256；标准effects、相应条款、共用规则或实际`resource-effects.mjs`变化后，旧证明不能继续将效果放入运行导出。验证不写证明；当前证明来自已通过的只读测试输出。修改相关机器规则后须重新核对并执行测试，再更新证明与生成物，不可手填“passed”。

待正式集成：选择要采用的候选，逐项登记实际学习来源与采用报价；其他资源仍须完成取得／XP事务和未编码语义，适配现引擎上述限制，补对应执行测试，再安装生成索引与数据。本包提供可审阅的机器源、有限已验证被动、一个已验证使用动作及该法术的学习政策，不声称这些集成步骤已完成。

## 本轮通用程序政策与治疗动作

标准`definition.programs.cast`内新增可复用的opt-in字段，无需修改共享schema：`executionPolicy`规定允许等级与固定威力、实际取得版本／来源／采用记录、所需专业与取得时绑定的能量池；`integerInputs`规定整数选择、默认值与实际上限；`targetPolicy`规定触及及活物。未声明这些字段的D/C程序继续走旧路径，现有26项程序测试通过。

治疗微伤的增幅量属于有上限的玩家选择，P与治疗比率仍由契约提供，分类器请求只选择已有操作计划。0增幅不读取缺失的最高施法者等级；正增幅才查询实际存档等级。绑定池必须有真实magic类型或有来源的取得资格记录，不能仅因“通用能量”而支付。目标存档生命类别优先，满A死亡者在支付前拒绝；自身治疗不要求额外触及距离。治疗分配只允许不重复的A/L/B，余下治疗点不跨次保存。

本地闭环由`resource-program-policy.test.mjs`实际经过`reduceRuleAction`及战斗`mechanism`，使用内存临时注册且finally恢复，不改正式注册表文件或真实存档。9项用例覆盖0魔力基础、合法增幅、L/A比率、取整与保存往返、超额不扣费、版本／专业／越权池拒绝、生命类型与死亡／接触／成分、治疗限制及一次标准动作支付。

`compiler/check-programs.py`只读运行`node --test --test-isolation=none --test-reporter=tap`，输出实际9项结果、契约program／action指纹及涉及执行模块和测试文件SHA256。成功输出记录于`execution/program-verification.json`；编译仅在证明与当前契约、正文、共享规则及所有相关代码hash一致时导出该program和白名单动作。证明失配则不能沿旧结果开放动作，验证脚本本身不写证明。


## 治疗微伤的学习闭环

`definition.learning.policy`声明无级、咒法资格和取得时绑定的实际魔力池，候选原价固定3XP；不要求帝国施法职能，也不把外树资源改为观澜树。报价继续使用现有字段，并追加`contractVersion:"2026-10-25.machine.4"`、`acquisitionChoices:{magicPool:"实际池名"}`。未有池类型的旧状态须由主持报价登记有来源的`acquisitionQualifications.energyPools`。定义注册、候选索引或`adopted:true`本身不授予资源；仍需真实人物资格、已开放成长窗口、实际学习来源和支付。

现有`growth-pricing.purchaseLearning`完成普通XP支付与分期，`resource-acquisition`验证声明资格。未采用、旧版本、错误报价、资格／魔力池不足、XP不足、重复购买均拒绝；学习完成保存`version/source/adoptionStatus/choices/qualifications`。0魔力余额不妨碍学习或基础施法，正增幅仍依真实等级和余额。观澜减费与悟法XP保持原用途隔离，此术按外树无级候选支付3普通XP。

独立的`compiler/check-acquisition.py`只读运行6项购买规则测试与3项主持／分类器／MVU流程测试。流程经过`registerRuleScene`（现有hostConfigure使用的入口）、已登记报价的分类器说明、`action:resource`、保存读回、消息继承及随后`cast`；重复操作幂等，询问、取消或错误悟法声明不花费普通XP，不改T0基线或其他人物。

`execution/acquisition-verification.json`分别固定学习价格、政策、身份、契约／阅读／共享规则与相关计价／取得／保存代码和测试hash；它不借用cast证明。编译仅向运行数据导出证明有效的学习政策，cast白名单仍只计1个主动动作，新增`verifiedAcquisitionTransactions:1`单列学习事务。没有学习证明时即使cast证明有效，也不导出该候选学习政策；旧价格或资格改变使证明失效。`verify.py`复跑两份证明并检查这项隔离。该候选尚未纳入六书资源条目，未部署；本轮没有为真实角色学习。
