# 魔幻能力组机械版

版本：`2026-10-25.magic.1`。从[双版本索引](execution/generated/机械版索引.md)选资源，每行都有阅读版和对应JSON。

这批机械版把**能力组本体**拆成分阶规则。例如法师的D阶必须选择奥术／火焰／冰霜，三者的施法DP加值各有适用条件；C阶的新收益另列，不把三个分支全授予人物。书籍继承总纲时引用同一取得记录，不额外开第二个池或重复取得职能。专有技艺仍须另学，原文明赠的法术才生成有条件的取得选择。

## 文件与用途

| 文件 | 内容与当前用途 |
| --- | --- |
| `阅读版/*.md` | 人工／模型审核的规则正文。 |
| `execution/contracts/*.rule.json` | 33份同版本机械契约，是唯一机器撰写源。 |
| `execution/shared.rule.json` | 本批共用动作标值和学习报价的有限规则；不修改901全局政策。 |
| `execution/generated/resource-selection-index.mjs` | 从契约生成的选材索引，供模型规划资源组合；选择不代表取得。 |
| `execution/generated/resource-contract-index.mjs` | 全部契约的ESM投影，供工具查阅结构化声明和来源。 |
| `execution/generated/resource-data.mjs` | 仅包含通过当前执行证明的被动片段。本批为阴影超魔使的强韧加值。 |
| `execution/generated/resource-action-index.mjs` | 可执行主动动作白名单；本批仍为空。 |
| `execution/generated/resource-blocked-index.mjs` | 尚未完整编码／接入的动作意图，不能发给执行器强行结算。 |
| `execution/generated/coverage.json` | 本体声明、公式、被动验证、动作和学习事务分别计数。 |

生成文件均不是第三份独立规则。改正文或合同后，旧哈希／证明失效；修改机械数据须直接编辑契约，再重新验证和生成。`compiler/seed_contracts.py`仅用于首次导入，拒绝覆盖已有契约；临时本体输入已内联并移除。

## 契约字段

- `identity`、`id`、`version`、`reading`锁定候选身份、正文和来源；六项已排除能力组不在本批。
- `definition.authoringOnly.baseMechanisms.stages`分别列每阶前提、授予、选择、效果、条件、叠加／替换和证据。公式采用既有有限AST，不执行字符串公式，也不接收模型给出的任意数值。
- `baseMechanisms.inputBindings`区分真实存档读值和结算上下文。传奇点数、实际战力、已选池、结算成功数等必须有实际依据，不能由世界T档或描述反推。尚未接通的上下文适配器明确标为`implementation-needed`。
- `authoringOnly.units`覆盖531个非空阅读条款，包含明确术卡字段、原价、动作价及本体机制引用。技能树的剩余内容仍有来源绑定及实现缺口；这**不表示全部技艺语义已经结构化完成**。
- `actions`中的未实现意图保持`operation:null`、`availability:blocked`，不会因为能找到正文就开放执行。
- `unresolvedRules`只列原文真正缺参；`implementationGaps`记录明确规则尚未编码或尚无实际消费者的工作。

## 当前可验证范围

本体共有132条阶位记录、390条效果声明，包含35个单书继承总纲的节点；这些不是390个已可执行效果。二十七S是源中未开放的非卖品记录，明确不可购买、无收益。

阴影超魔使D/C/B的强韧收益分别为3/6/9内在DP，已验证实际`saveProfile`读入、同类取高、版本／资格与阶位门控、非强韧不生效及JSON读回。该证明不覆盖生命加值、黑暗分类、超魔、整包学习或其他能力。

共用动作换算和候选报价只做纯计算验证，不实际预支角色动作或扣XP。研读兑现公式验证有限额度及只补差额，但完整研读事务尚未接入。所有本体取得、主动机制、整棵技能树仍须逐项接通消费者及持久化，才能进入执行白名单。

真正缺参为4组、11个分支，见[集中表](未决项.md#source-gaps)：灵魂法师8条空术、失能巫师S职能价、夜天治愈之风动作、杂学士狡黠击破动作。其他未实现条款不要求用户补规则。

## 本地验证与生成

在资源库根目录运行：

```bash
python outputs/施法体系适配-20261024/_validate.py
python outputs/施法体系适配-20261024/compiler/compile.py --check
python outputs/施法体系适配-20261024/compiler/verify.py
```

`verify.py`只读复跑来源／格式、30项被动场景断言、3项动作报价测试和6项独立语义测试；不会自动更新证明来掩盖差异。阅读稿经过授权修订后，可显式运行`_validate.py --refresh`更新阅读清单；随后人工核对相应合同和证明，再运行`compile.py`生成投影。

本批未替换主仓库的技艺候选注册表，未投影进六书或安装到实际运行环境，也没有创建NPC或修改T0。现在可用这批双版本资料规划NPC选材；需要JS自动结算时，只选取已接入部分或继续实现所选机制。
